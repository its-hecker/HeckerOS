# HeckerVPN TCP startup and connection testing — 9 November 2026

## TCP startup failure on Wi-Fi

The supplied Wi-Fi capture reports startup marker `4 5 0`: configuration phase,
rejected category, no system errno. Three attempts fail before `hkvpn0` exists.
The installed core SHA-256 matches the previously pinned WhiteVPN 1.7.1 core.
The optional `/proc/net/tcp` and `/proc/stat` denials do not establish the cause.

The decisive source difference is the Android-only `unmarshalWhiteVPNConfig`
path in [WhiteDNS's pinned core](https://github.com/WhiteDNS/mihomo/blob/05fb40f89637aa27d81b638bff765a6d57797cdb/config/whitevpn_policy.go).
It rejects several keys HeckerVPN emits, then requires WhiteVPN's authenticated
loopback controller, mixed port 2080 and DNS listener 1053. The earlier generic
Linux Mihomo parser test never exercised this Android-specific policy.

Replace that asset with the official FlClash 0.8.92 arm64 core. Its C ABI matches
the production bridge, and its corresponding parser has no WhiteVPN-only gate.
The pinned source and release hashes are recorded in `prebuilts/mihomo`.
FlClash 0.9.x has a different Android API and cannot be substituted directly.
Preparation upgrades the known previous core atomically; unknown local changes
still fail checksum verification. No proxy/controller listening ports are enabled.

This fixes the identified configuration incompatibility at source level. Actual
TCP traffic on the phone, starting with Wi-Fi, must still be verified after flashing.
ONIC-specific transport investigation remains a later step.

## Connection testing

Open **HeckerVPN**. A connection-testing card and scrollable live result log sit
above the current connection card.

- Test all saved profiles plus supported entries already in the refreshed free
  TCP catalog, or filter the batch to WireGuard/TCP. Duplicate catalog entries
  already saved as profiles are not tested twice.
- Each saved profile also has **Test this profile**.
- The log lists every target, its queued/current state, final outcome, measured
  HTTPS latency and bounded TCP startup detail when available.
- WireGuard must produce a fresh handshake and pass tunnel-bound HTTPS. An open
  endpoint port or ICMP ping alone never produces a Working result.
- TCP must pass its native HTTPS and tunnel DNS checks, then the same HTTPS
  internet check. Startup, configuration/endpoint DNS, setup, handshake and
  internet-check failures have separate results.
- Connectivity checks have a 15-second budget after native setup. Native startup
  has its own timeout. Tests run sequentially because this backend owns one TUN.
- **Include a 1 MiB download** is off by default. A working target can download
  up to 1 MiB from Cloudflare; Mbps includes connection setup time. A failed
  download leaves the successful connectivity result and shows Speed unavailable.
- **Stop tests** cancels the current operation and the queue. Closing the native
  lease interrupts core waits and setup helpers; cleanup helpers are allowed to
  finish. The user can also stop from the ongoing test notification.
- A network handoff stops the batch. Old results show their network/time and are
  marked stale when the current network differs.
- **Share test results** opens Android's share sheet with result text. No profile
  configuration, private key, account credentials or proxy authentication is exported.

Testing temporarily disconnects an active HeckerVPN session, uses a temporary
controller-only app route, confirms cleanup, and reconnects the previously selected
profile when finished or stopped. Saved configurations, selection and app policies
are not modified by testing. Other connection mutations are rejected during a batch.
The testing card explains this before the user starts. An explicit disconnect
request cancels testing without automatically reconnecting.

New UI/notification strings include English, Russian and Simplified Chinese.

## Validation

- Production native daemon, WireGuard helper and core bridge compile with warnings
  treated as errors. Native tests cover control-lease cancellation during an otherwise
  blocked core read, half-close detection and returned tunnel network IDs.
- Locked arm64 ELF symbols and checksums pass. The matching official Linux release
  runs the generated configuration through its real `initClash` and `setupConfig`
  actions and returns the expected traffic shape. This checks configuration application,
  beyond a generic upstream parser's syntax-only test.
- Real Android SDK Java compilation, AIDL generation and Android resource linking
  pass for the controller, HeckerVPN UI and QS tile.
- Production batch-runner fixtures exercise both protocols, controller-only routing,
  tunnel-bound HTTPS, speed limits, continuation after startup failure, no-handshake
  classification, network changes, cancellation and credential-free result snapshots.
- Existing VPN Binder/client, QS state, configuration, provider and source checks pass.

The host release check does not run Android's loader or an enforcing-phone TUN.
A full ROM build and physical Wi-Fi, other mobile-network and ONIC tests remain.

## Coral build

From the existing Coral build directory:

```sh
cd ~/heckeros-coral &&
python3 vendor/hecker/floral/suite/tools/prepare.py --rom-root "$PWD" --revert &&
repo init -u https://github.com/its-hecker/HeckerOS.git -b fix/vpn-tests-20261109 --git-lfs &&
git -C .repo/local_manifests fetch origin fix/vpn-tests-20261109 &&
git -C .repo/local_manifests switch --detach FETCH_HEAD &&
repo sync -c --fail-fast --no-clone-bundle --no-tags &&
env -u HECKER_BUILD_JOBS USE_RBE=true HECKER_DEVICE=coral HECKER_BUILD_VARIANT=userdebug bash .repo/local_manifests/build.sh
```

The matching local-manifest branch pins this Suite update and retains the existing
XDA device, framework, Settings, vendor and kernel inputs.
