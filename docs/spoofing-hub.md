# Spoofing hub

Settings > Hecker's Suite > **Spoofing hub** replaces the old Play Integrity
entry. The private native Settings host contains the grouped TrickyStore and
Play Integrity Fix pages, target-app search and Auto / Leaf / Cert / Skip modes.
The original fingerprint/key Lottie is generated by
`tools/generate_suite_previews.py`; its rendered preview is
[spoofing.gif](previews/spoofing.gif). Animation stops offscreen and respects
reduced motion and power saving.

This is a Java/native View adaptation of those screens to HeckerOS Settings,
with the crDroid/Evolution X Apache-2.0 attributions preserved. It retains the
existing HeckerOS Android 17 Axion-derived process and keystore integration;
Evolver's complete Compose app and framework are not substituted into the ROM.
The five certificate/TrickyStore classes now incorporate Evolution X’s Android 17 backend updates from the same immutable framework revision, rechecked unchanged at current `cnb` head `c4d3eeb6aba62768dfb11c26711728b99daa42dd` on 26 October. HeckerOS retains its working Android 17 lightweight signer, private importer and UID boundaries. Exact owned file hashes and build revisions are in
`integration/platform-features.json` and `integration/source-revisions.json`.

## Controls and persistence

TrickyStore has an independent master switch, fetch/import/delete controls,
live certificate/revocation checks, target import, bulk verification mode and
patch-date editing. Disabling it retains the stored keybox and targets. The
four native modes accept `target.txt` suffixes (none / `?` / `!` / `-`) and the
existing JSON format. An explicit empty target list stays empty. Reset selects
eligible installed Google packages. Core/shared system UIDs, secondary users,
isolated processes and Xposed managers remain excluded by the native service;
imported protected entries can be removed but cannot gain keybox access.
Shared app-UID packages share that UID's effective configuration.

The PIF page fetches the selected Pixel's newest numeric Canary build from
Google Flash Tool metadata. It discovers current Pixel model names from the
Android developer download pages, never substitutes a bundled sample, and
does not download an OTA or factory image. Import supports validated JSON and
property files. Active build fields can be edited; advanced switches preserve
the native backend's defaults. Reset removes advanced overrides. Delete removes
the custom profile; the separate master switch disables both the custom PIF
path and the legacy GMS/Play Store fallback after those processes restart.
Photos and unrelated per-app profiles retain their existing behavior.
The explicit restart control force-stops Play services and Play Store without
clearing data. They restart when needed.

Keyboxes are not bundled. An explicit Fetch action reads Evolution X's public
keybox repository. Fetch verifies certificate chains, trusted Google roots and validity dates, and checks Google’s live revocation response before the atomic native importer validates key/certificate pairing. Like Evolution X, manual fetch may save a trusted chain when live revocation is unavailable; its status stays Unknown and the UI explicitly says it is unverified. Revoked, suspended, expired, not-yet-valid, untrusted and malformed chains are rejected with the actual reason. Public trust anchors can fall back to a previously fetched cache. Failed downloads keep the previous keybox; successful fetch restarts Google services so process caches reload. XML entities, oversized files and empty imports are
rejected. An unavailable revocation response is **not verified**, never Valid.
The displayed certificate status is not a Play Integrity verdict. The Canary
refresh estimate is labelled as an estimate derived from the patch month.

Private key material remains in the existing system-only 0600 atomic files.
The new private OPTIONS record controls TrickyStore without exposing the record
to apps. Apps receive only their UID's targets; Skip targets receive no keybox
or patch data. Public PIF metadata and its enable switch remain privileged
Global settings. The Suite service UID cannot read or manage private keys.
The legacy private `HeckerIntegrityActivity` redirects to the hub.

Automatic refresh is off until enabled. Its persisted daily job requires an
unmetered network and observes both master switches. It refreshes missing/stale
Canary metadata and missing/invalid provider-owned keyboxes; user-imported or
edited profiles and user-owned/legacy keyboxes are preserved. Checks are
throttled, and writes compare the configuration again after network work.
Disabling refresh cancels the job. Neither opening the hub nor the host tests
fetches a provider keybox automatically.

## Validation and upgrade

`tools/check_spoofing_hub.py` runs the actual import/discovery/network-policy
and certificate code against the locked Android 17 implementation JAR. It uses
synthetic EC/RSA certificate chains and no provider key material or network.
`tools/check_spoofing.py` exercises the native store, UID isolation, master
switch, Skip mode, atomic import rejection and real RSA/EC certificate hooks.
`tools/check_platform_features.py` compiles the Settings Java/resources against
the locked SDK, and the regular Suite source/SDK/native-adapter checks remain
required. These checks run in CI with JDK 21.

The change spans **Suite, Settings and frameworks/base**. Before syncing the
new revisions into an already prepared checkout, run the old Suite's guarded
`tools/prepare.py --revert` from the Android root. This removes generated source
adapters while retaining unknown edits (or stops for review). Pull the local
manifest, sync all three projects, then run the existing build helper to
reapply adapters. Do not reset or force-sync a dirty project to bypass a conflict.

A full Soong/ROM build and Coral UI/network/device checks remain required. Test
light/dark theme, large fonts, rotation/import return, reduced motion, scrolling,
all target modes, enable/disable with app restarts and actual attestation
results on the phone. Host certificate checks establish no Google verdict.
